# Frontend

- Requires universal responsiveness — every screen and layout must adapt fluidly across mobile devices, desktop monitors, and large TV displays. Confidence: 0.9
- Strict visual style retention: the existing design aesthetic (e.g. glassmorphism) and styling must be preserved during refactors. Confidence: 0.85
- Prefers a globally centralized theme engine so toggling dark/light mode, accent colors, or typography in one spot instantly reflects across the whole app. Confidence: 0.8
- Prefers responsive typography that scales dynamically based on screen breakpoints. Confidence: 0.7
- Expects every UI surface — including table text/backgrounds and settings "live preview" widgets — to be theme-token-driven and update instantly when theme or accent changes, never relying on stale or hard-coded colors. Confidence: 0.7
- Prefers constrained dropdown/select inputs over free-text fields for values with a fixed valid set (e.g. timezones), populated with the valid options and backed by server-side validation that rejects anything not on the list. Confidence: 0.85
- Expects a tenant/institution setting such as timezone to save and immediately reflect across that tenant's operational context (dates, reports and reminders rendering in the workspace's own zone). Confidence: 0.75
- Wants smooth, modern, context-appropriate loading states: spinners on submitting/processing buttons and animated page/modal transitions (overlay fade-in, panel rise). Confidence: 0.85
- Expects localization to translate the whole UI instantly on language change while user-entered database content (names, notes, free-text records) stays strictly in its original language. Confidence: 0.8
- Keeps the language selector inside User Settings rather than the global top bar. Confidence: 0.7
- Prefers consolidating related interface preferences into one General/Theme settings manager instead of maintaining sparse standalone settings modules (e.g. folding language selection and hint toggles directly into the theme/general settings screen). Confidence: 0.6
- Wants internationalization built as a single central language hub — one registry every subsystem reads, plus one command/flow to add a new language that scaffolds its files and registers it — so adding a language on top of existing ones is smooth, additive and requires no per-language or per-feature code changes. Confidence: 0.8
- Prefers a persistently mounted SPA shell: switching modules must not re-render, blink or reload the global sidebar — only the content body swaps via client-side routing, and the sidebar's active selection updates immediately without re-fetching itself. Confidence: 0.75
- Prefers structured, namespaced translation keys (e.g. `dashboard.metrics.total_users`) over raw English sentences used as keys. Confidence: 0.65
- Wants the language registry to be database-driven and manageable at runtime through a Super Admin CRUD control panel (add/edit languages, upload flag icons, toggle is_active / is_default) rather than hard-coded in config, with only active languages offered in the end-user switcher and a graceful fallback to the default language for unknown or inactive codes. Confidence: 0.7
- Wants layouts written with direction-agnostic, logical CSS (flex + gap, margin-inline / `ms-*` / `me-*`) instead of physical directional properties (`margin-left`, `space-x-*`), so the UI mirrors cleanly for future RTL languages and tolerates translated text of varying length. Confidence: 0.7
- Wants standard Laravel + Inertia.js + React frontend architecture kept out-of-the-box: a single Vite entry (`@vite(['resources/js/app.jsx'])`) in the `<head>` alongside `@inertiaHead`, `@inertia` rendered inside the `<body>`, and `app.jsx` using a plain `createInertiaApp` setup with pages resolved client-side via `import.meta.glob` — no per-page Vite entry points and no manual `#app` guard logic. Confidence: 0.8
- Wants a clean, light, modern intro/login panel that matches the platform theme, with a smooth, subtle background animation (CSS keyframe gradients or lightweight Framer Motion) to make the entry experience visually engaging. Confidence: 0.6
- Wants monitoring/board views (manager dashboards, tallies, activity feeds) to have real-time visibility — new activity should appear without a manual page reload, e.g. boards that self-refresh periodically or push updates. Confidence: 0.6
- Wants interactive help-hint badges (`?`) placed inside the main content body of every card, section and module platform-wide, scoped so they never overflow or hide behind sidebars, driven by a single global user-settings toggle that shows/hides them instantly and translated with the active language. Confidence: 0.65
- Prefers related features consolidated into a single cohesive module hub with one grouped navigation section, explicitly eliminating fragmented/spread-out navigation across separate menu areas. Confidence: 0.65
- Wants genuinely distinct domains kept strictly separate: functionally unrelated concerns (e.g. financial/out-of-pocket expense claims vs meal-count claims) belong in their own dedicated module and navigation section, never mingled inside one another's module, with cross-links pointing to the sibling module. Confidence: 0.6
